## Context

现有实现见 `neatquit/NeatQuit/ScheduledAction.swift`、`ScheduledActionScheduler.swift`、`ScheduledActionStore.swift` 与 `SchedulePanelView.swift`：一条规则只有「目标 + 绝对触发时刻」，调度器每 2 秒 tick 一次，菜单按 `fireAt` 计算剩余时间。磁盘面板只有「磁盘 + 倒计时」两个输入。

闲置模式受两个平台事实约束：

- macOS 没有「空闲时长」字段，只有 `IOBlockStorageDriver` 的累计读写计数，必须自己采样求增量。
- 页缓存命中的读不产生磁盘 I/O，所以「计数没有增长」不等于「没有进程在用」。

实测（本机，60 秒、2 秒采样）：

| 目标 | 结果 |
|---|---|
| Ventoy（exFAT U 盘，`disk4`） | 30 个采样点全部静默，累计 0 字节 |
| 测试用 APFS DMG | 有独立 `IOBlockStorageDriver`，计数可读 |
| 内置盘 | 60 秒约 1.46 GB，计数正常（内置盘不在可弹出范围） |
| APFS 合成盘（`disk1/2/3/6`） | 都指向同一个物理驱动 |

最后一行决定了采样单位必须是整盘：按卷采样会把同一块盘算成多份，也会漏掉其他卷的读写。

## Goals / Non-Goals

**Goals:**

- 在现有弹出面板内以单选方式加入闲置触发，复用时长控件，不新增第二套面板。
- 用最小运行时开销判断「整盘是否连续 N 分钟无读写」，不新增常驻定时器。
- 闲置失败不制造噪声：把「被占用」优先解释为「还在用」，同时保留最终可见的失败出口。
- 旧数据无需用户操作即可继续工作。

**Non-Goals:**

- 不做「常驻规则」：本变更的闲置规则仍是一次性的，磁盘重新挂载后需要重新设置。
- 不做进程级归因（哪个 App 在用盘），也不引入 `lsof`、`fs_usage` 或特权 helper。
- 不为闲置模式引入系统通知、后台登录项或新的权限。
- 不改动定时退出应用面板。

## Decisions

### 1. 触发方式进入数据模型，而不是复制一套闲置规则

`ScheduledAction` 增加触发方式：

```
Trigger
  .at(Date)                     // 倒计时，沿用现有 fireAt
  .idle(seconds: TimeInterval)  // 闲置阈值
```

- `nextFireDate` 对 `.at` 直接返回日期；对 `.idle` 返回「运行时闲置起点 + 阈值」。菜单、排序、聚合入口继续只依赖这一个值，避免在每个调用点分支。
- 备选方案是新增 `IdleEjectRule` 集合，与现有规则并行。它会让持久化、未完成状态、重试、菜单各复制一份，否决。
- 备选方案是只存一个 `mode` 标志并继续复用 `fireAt`。闲置的 `fireAt` 是派生值，写回存储会在睡眠/重启后漂移，否决。

### 2. 闲置起点只存在内存，不落盘

`lastActiveAt` 每个采样点都可能变化。若随 `@Published actions` 更新并 `persist()`，会产生每 2 秒一次的偏好写入和无意义的菜单重建。

- 规则持久化「方式 + 时长 + 磁盘标识」；`fireAt` 始终写出（倒计时为真实时刻，闲置为近似值，供旧版本降级读取）。
- 闲置的 `fireAt` 是「闲置起点 + 阈值」的派生值，保存在内存中的 action 上；检测到读写时原地刷新，不落盘。
- 失败顺延会把条目从 `firing` 拉回 `armed`，此时补写一次，避免重启丢规则；活动刷新不写盘。
- 菜单标题直接读 action 上的派生 `fireAt`，与倒计时共用同一套剩余时间计算。

### 3. 采样：整盘累计计数 + 2 秒增量

新增 `DiskActivityMonitor`：

```
bsdName -> IOMedia(Whole) -> 向上找到 IOBlockStorageDriver
        -> 读取 Statistics 的 Bytes(Read) + Bytes(Written)
        -> 与上次采样相减
```

- 只对存在闲置规则的目标采样；没有闲置规则时整条路径不执行，零开销。
- 解析出的驱动条目按 bsdName 缓存，磁盘消失时释放并允许重新解析。
- 累计计数不会漏掉两次 tick 之间的 I/O，只会在下一个 2 秒窗口体现；判定精度足够。
- 备选方案是 `iostat` 或 `fs_usage` 子进程：引入进程管理、权限与解析成本，否决。

### 4. 活动判定：增量大于零即算活动

不做字节阈值过滤。理由是任何阈值都无法区分「用户保存了一个小文件」与「系统写元数据」，而失败顺延机制已经能兜住「看起来闲置但仍在用」的情况。若后续实测发现系统噪声导致规则永不触发，再引入「持续活动」或阈值，不改模型。

### 5. 闲置失败：顺延优先，连续 3 次才标记

```
到点 -> eject
  |         |
成功      失败
  |         |
移除    闲置起点 = now
          连续失败 +1
             |
        检测到读写? -- 是 --> 失败计数清零
             |
        连续失败 >= 3 ? -- 是 --> 标记未弹出 + 角标
```

- 「失败」在闲置语境下更可能是「进程还开着文件」，直接标记会让看视频、开着文档的用户频繁看到角标。
- 计数在检测到读写时清零，因此真正「无 I/O 但被卡住」的磁盘仍会在 3 个周期后浮出水面。
- 倒计时规则保持原有「失败即未弹出、不自动重试」，因为它的触发是用户明确指定的时刻。

### 6. 睡眠与重启都重置闲置起点

- 唤醒：监听 `NSWorkspace.didWakeNotification`，或在下一次 tick 发现间隔超过 60 秒时视为睡眠边界，统一重置。
- 重启：启动时把所有闲置规则的起点置为启动时刻。
- 理由：避免「合盖一夜，掀盖瞬间盘被弹掉」；同时让授权恢复引发的自我重启不会造成意外弹出。
- 备选方案是按墙钟累计（睡醒立即弹）。语义更字面，但对笔记本用户过于突然，且与现有「5 分钟补跑」的保守取向不一致。

### 7. 面板：磁盘弹出的唯一操作入口

`EjectPanelView` 由「添加定时弹出」升级为「磁盘弹出」，包含：

- 磁盘下拉与「立即弹出」按钮；立即弹出作用于当前所选磁盘，不创建规则，失败沿用现有提示，成功后关闭面板。
- 「弹出方式」单选（倒计时 / 闲置超时）与 `DurationSelector`，只切换标签、说明与主按钮文案。
- 「当前规则」行，仅当所选磁盘已有规则时出现：显示方式与剩余时间，并提供「取消规则」。
- 打开面板时按该磁盘已有规则预选方式与时长；「自定义」仍进入自定义输入。
- 若所选磁盘读不到活动计数，闲置选项置灰并显示原因，提交按钮只允许倒计时。

备选方案是把立即弹出留在菜单里单独开一个小面板，但那会重新引入两个入口，与「统一参数设置」的目标冲突，否决。

### 8. 菜单：磁盘段收敛为单一入口

- 删除逐盘快捷行（`diskQuickItem`、`diskRows`、菜单时长预设与 `startDiskEjectFromPreset`）。
- 没有规则时，入口显示「磁盘弹出…」，点击直接打开面板。
- 有规则时，入口显示最早到期规则的剩余时间，展开为待执行清单、「添加弹出规则…」与「全部取消」。
- 待执行清单中的闲置行显示「闲置 30 分钟 · 18:00」；最近一次采样有读写时显示「使用中」。
- 菜单打开期间的 1 秒刷新只改标题，不增删条目，沿用现有约束。
- 代价是 5/15/30 分钟预设从「菜单一步」变成「打开面板 + 选时长 + 开始」；用一致性换一次点击。

### 9. 持久化：同一存储键，解码向后兼容

不新增存储键。编码时始终写出 `fireAt`（倒计时为真实时刻；闲置为「编码时刻 + 阈值」）以及 `mode` / `idleSeconds`，解码时优先读 `mode`，缺失则按倒计时处理。

这样旧版本回退时仍能解出记录并按倒计时执行，不会因为解码失败丢掉整份规则列表。

### 10. 计数不可用时宁可不动

- 创建前面板检查一次；不可用则禁用闲置选项。
- 运行期间读取失败按「有活动」处理，重置起点，绝不据此触发弹出。

## Risks / Trade-offs

- **[缓存命中导致误判闲置]** → 失败顺延把误判转化为一次无害的重试；菜单显示「使用中 / 剩余时间」让状态可解释。
- **[系统索引或备份让盘永不闲置]** → 规则不会触发，但不会误弹；用户可随时取消。后续可按实测引入阈值，不改模型。
- **[连续失败计数导致延迟可见]** → 阈值越大，3 次失败浮出的时间越长（30 分钟阈值约 1.5 小时）；这是用可见性换噪声的取舍。
- **[主线程读 IORegistry]** → 只在有闲置规则时执行，且解析结果缓存；实测属性读取为微秒级，2 秒一次可接受。
- **[一次性规则不符合「设一次管很久」的预期]** → 面板说明与待执行清单明确「触发后移除」；常驻规则作为后续独立变更评估。
- **[失去一键预设]** → 高频用户每次要多点两下；面板保留 5/15/30/60/120 预设，且打开面板时按已有规则预选，避免重复配置。
- **[立即弹出与定时提交相邻]** → 立即弹出放在磁盘下拉旁而不是主按钮旁，降低误点概率；它仍然是一次显式操作，不需要额外确认。
- **[降级到旧版本]** → 旧版本会把闲置规则当成倒计时执行（编码时写入了近似 `fireAt`），行为可接受但不完全等价。
- **[DMG 等活动计数依赖虚拟驱动]** → 实测可用；若某个镜像类型不提供计数，按「不可用」处理。

## Migration Plan

1. 解码兼容先落地：旧记录按倒计时读取，现有规则不受影响。
2. 新字段只增不改；不迁移存储键，回滚时旧版本仍可解码。
3. 发布前用 DMG 做一次端到端验证：占用时不弹、静默后弹出、失败顺延与第 3 次标记。
