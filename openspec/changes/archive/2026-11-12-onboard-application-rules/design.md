## Context

参见 proposal.md。RuleStore 默认 .allExceptListed，只有用户修改后才保存列表；因此“没有列表键”不能证明是新用户。NeatQuitApp 启动时配置监听、授权回调和菜单；规则编辑已有授权入口。SettingsView 提供模式选择和列表增删。当前没有可复用的首次规则引导状态。

## Goals / Non-Goals

**Goals:** 分离首次使用判定与列表缺失判定，复用规则管理和授权路径，中英文同步。

**Non-Goals:** 不改窗口识别、默认启用状态、键盘开关、试用时长或授权边界；不增加默认恢复按钮和强制配置向导。

## Decisions

- 提取现有预置集合为旧默认集合；新默认集合只追加 com.apple.MobileSMS 和 com.apple.Terminal，以稳定 bundle ID 匹配。新安装采用新集合。
- 在初始化任何会写入偏好或启动试用的组件前，读取既有偏好中的 enabled、keyboardEnabled、规则模式、两套规则列表及既有试用/授权记录的存在性，生成首次使用快照。不把 false、空列表或过期试用当成无记录。拒绝仅检查规则键或引导键，因为会误判老用户。
- 有使用记录而没有列表键时，把旧默认集合作为迁移结果持久化；已有列表原样保留。损坏数据不作为全新安装证据，沿用既有回退集合，避免因修复引入新增排除项。
- 用独立本地引导版本/已处理状态记录是否完成。升级用户迁移为已处理；全新用户只有明确操作才标记。内存单窗口防止启动与授权回调重复展示，不提前写完成状态。
- 新增轻量规则说明窗口，从现有 RuleStore 读取列表；调整按钮调用现有规则管理入口（包括授权检查），而非另建编辑器。关闭等同稍后处理。启动在菜单可用后展示，不等待辅助功能许可，也不和授权提示互相覆盖；权限提示优先时规则窗口排队展示。
- 试用到期行为复用现有 applyLicenseState 与监控策略，不新增规则失效/删除逻辑。首屏准确说明编辑权限，避免把默认预置保护与可编辑权限混为一谈。

## Risks / Trade-offs

- 老用户可能从未改偏好 → 启动早期读取多种既有状态，不以单键决定；无法区分完全清空所有状态与全新安装，两者视作新安装。
- 默认增加终端排除会改变新用户行为 → 引导展示列表，用户可在现有权限下移除；不覆盖老用户。
- 自动权限恢复重启导致引导重复 → 处理状态持久化，异常退出不记完成；模拟授权重启验证。
- 新截图/文案需要同步 → 核查中英文界面和规则说明，不在本次规格阶段修改营销素材。

## Migration Plan

先读取旧状态，执行幂等迁移，再初始化正常运行组件。保留原模式和两套规则键结构。引导使用独立键；回退旧版本时忽略新引导键，已保存列表继续兼容。验证新安装、老默认用户、自定义空列表、仅包含模式、损坏列表和重复迁移。
